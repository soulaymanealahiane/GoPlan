# Google tag installation

The owner-supplied Google Tag Manager container is `GTM-KQJH88L5`. Its public published script returned HTTP 200 and contained the GA4 destination `G-HPWJJGHLSR` during installation on 6 November 2026. Container configuration can change separately from the application.

The exact current Google bootstrap supplied by the owner appears immediately after `<head>` once in every HTML source under `dist/` and in `admin/index.html`. `server/google-tag.mjs` supplies the same bootstrap to the dynamic anonymous/non-owner admin gate, which now has explicit head/body elements. Runtime aliases such as `/`, `/demo` and `/admin` serve those same tagged documents. The generated Worker embeds the tagged source. No second GA4 configuration or legacy GTM noscript snippet is added, avoiding duplicate container initialization. Google's current [installation guide](https://support.google.com/tagmanager/answer/14847097?hl=en) describes this unified snippet.

This includes sign-in, saved-plan/demo and operations pages as requested. There is no extra site consent prompt. Existing first-party GoPlan analytics continues independently, with its current bot/owner/privacy-signal exclusions; those exclusions are not automatically applied to Google's container. Google can count owner/admin visits, so the reports may differ.

The bootstrap pushes only the standard initialization date into `dataLayer`. GoPlan adds no custom Google events or user/profile/form/academic payloads in this change. Any Google or third-party tags and their automatic measurement behavior remain controlled by the container settings. Privacy information now distinguishes Google's processing from GoPlan's own database counters and retention. Loading the container and inspecting its public configuration do not by themselves prove that a particular event reached Analytics Realtime.

`verify-google-tag.mjs` checks placement and uniqueness across all HTML sources and both dynamic gate states, preserves authentication behavior, and executes the actual inline bootstrap against a synthetic browser global to verify one initialization and preservation of an existing data layer. The compiled-Worker probe checks the rendered public, demo and owner/gated admin routes. These offline checks do not contact Google or submit test events. Live verification checks served markup and the published container, with minimal ordinary browser checks rather than synthetic visitor traffic.
